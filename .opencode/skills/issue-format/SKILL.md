# Issue Format

Follow this format whenever writing a GitHub issue for this project.

## Structure

### 1. Title

Concise, imperative, 50 characters or fewer.

### 2. Context

Why this work is needed. Reference the relevant part of `docs/spec.md`
whenever possible.

### 3. Requirements

A checklist of concrete, verifiable acceptance criteria.

- [ ] Example requirement
- [ ] Another requirement

### 4. Notes

Anything else relevant: affected files, links, dependencies on other
issues, or unresolved questions.

## Rules

- Requirements must be actionable and independently verifiable.
- Reference `docs/spec.md` for technical direction before proposing changes.
- Keep the issue focused on a single deliverable.
